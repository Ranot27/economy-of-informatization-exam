Экономическая постановка задачи¶

Проблема. Компания «ГородСоцСеть» запускает социальную сеть для города с населением 1 млн человек. У соцсети есть прямой сетевой эффект: чем больше в ней людей, тем она полезнее каждому. Пока пользователей мало, сеть малополезна и убыточна. После критической массы она начинает поддерживать себя сама.

Актуальность. Для платформы главный вопрос — не «сколько стоит разработка», а «хватит ли денег дожить до критической массы». От ответа зависят объем инвестиций и стратегия запуска.

Цель. Оценить ценность сети, найти момент достижения критической массы и эффективность проекта за 36 месяцев.

Задачи:

  1. найти критическую массу и срок ее достижения;
  2. посчитать ценность сети по закону Мэткалфа, доход и прибыль по месяцам;
  3. посчитать NPV, проверить его при других темпах роста и найти минимальный ARPU;
  4. оценить, сколько стоит ускорение на 6 месяцев, и предложить стратегию.

2. Расчеты¶

2.1. Математическая модель¶

Критическая масса. Доход $ARPU \cdot N$ должен покрывать затраты на поддержание $F$:

$$N_{крит} = \frac{F}{ARPU}$$

Время достижения. При росте на долю $g$ в месяц $N_t = N_0 (1+g)^t$, откуда

$$t_{крит} = \frac{\ln(N_{крит} / N_0)}{\ln(1+g)}$$

Ценность сети (закон Мэткалфа): $V(N) = k \cdot N^2$.

Доход: $R_t = ARPU \cdot N_t$.

Прибыль: $П_t = R_t - F - CAC \cdot (N_t - N_{t-1})$, где $N_t - N_{t-1}$ — новые пользователи месяца.

NPV: $NPV = \sum_{t=1}^{36} \dfrac{П_t}{(1+r)^t}$, где $r$ = 1% в месяц.

Почему эти методы. Закон Мэткалфа — основная модель прямого сетевого эффекта в лекции №3. NPV нужен, потому что сеть сначала несет убытки, а доходы получает позже: сравнивать их можно только с учетом стоимости денег во времени.

2.2. Модель роста сети¶

Четыре короткие функции. Главная — simulate: она месяц за месяцем считает пользователей, доход, затраты и прибыль.

def critical_mass(p):
    """Критическая масса: доход ARPU × N покрывает затраты на поддержание."""
    return p["support"] / p["arpu"]


def simulate(p, months=None, extra_start_users=0, free_growth_after=False,
             threshold=None):
    """Помесячная модель сети: пользователи, доход, затраты, прибыль.

    months            — сколько месяцев считать (по умолчанию горизонт из p);
    extra_start_users — сколько пользователей докупаем разово на старте;
    free_growth_after — True: после критической массы рост бесплатный (без CAC);
    threshold         — порог смены темпа роста (по умолчанию критическая масса).
    """
    months = months or p["months"]
    if threshold is None:
        threshold = critical_mass(p)
    users = p["start_users"] + extra_start_users

    # Месяц 0 — старт: дохода еще нет, платим только за докупленных пользователей
    rows = [{"Месяц": 0, "Пользователи": users, "Новые": extra_start_users,
             "Доход": 0.0, "Поддержание": 0.0,
             "Привлечение": p["cac"] * extra_start_users}]

    for month in range(1, months + 1):
        reached = users >= threshold - 1e-6             # критическая масса уже набрана?
        growth = p["growth_after"] if reached else p["growth_before"]
        users_now = min(p["market"], users * (1 + growth))   # не больше рынка
        new_users = users_now - users
        is_free = free_growth_after and reached          # за этот рост платить не нужно
        rows.append({"Месяц": month, "Пользователи": users_now, "Новые": new_users,
                     "Доход": p["arpu"] * users_now, "Поддержание": p["support"],
                     "Привлечение": 0.0 if is_free else p["cac"] * new_users})
        users = users_now

    table = pd.DataFrame(rows).set_index("Месяц")
    table["Ценность"] = p["k"] * table["Пользователи"] ** 2          # закон Мэткалфа
    table["Прибыль"] = table["Доход"] - table["Поддержание"] - table["Привлечение"]
    table["Дисконт"] = 1 / (1 + p["rate"]) ** table.index            # коэффициент месяца
    table["Дисконтированная прибыль"] = table["Прибыль"] * table["Дисконт"]
    return table


def npv(table):
    """NPV: сумма дисконтированных месячных прибылей."""
    return table["Дисконтированная прибыль"].sum()


def month_reached(table, level):
    """Первый месяц, когда пользователей не меньше level (None — не достигнуто)."""
    hit = table.index[table["Пользователи"] >= level - 1e-6]
    return int(hit[0]) if len(hit) else None


def when(month):
    """Текст для вывода: «на 112-м месяце» или «не за 180 месяцев»."""
    return f"на {month}-м месяце" if month else f"не за {LONG_MONTHS} месяцев"

Округляем вверх: 133 334 пользователей — 13,3% населения города

Как учтен CAC. В условии сказано: «доход ≥ затраты на поддержание + CAC». Если сеть растет на долю $g$ в месяц и за рост платит из дохода, новых пользователей за месяц $g \cdot N$, и условие превращается в

$$ARPU \cdot N \ge F + CAC \cdot g \cdot N \quad\Rightarrow\quad N_{крит}(g) = \frac{F}{ARPU - CAC \cdot g}$$

def months_to(level, growth):
    """Сколько месяцев роста с темпом growth нужно, чтобы дойти до level."""
    return math.log(level / BASE["start_users"]) / math.log(1 + growth)

2.7. Сравнение стратегий запуска (сверх условия, к заданию 10)¶

Привлечение до критической массы стоит одинаково при любой скорости, а поддержание оплачивается каждый месяц ожидания. Отсюда идея «рывка»: купить всех недостающих пользователей сразу. Сравниваем три варианта. Они отличаются тем, платным или бесплатным (органическим) будет рост после критической массы.

# Три стратегии: аргументы для функции simulate
strategies = {
    "Медленный рост (по условию)": {},
    "Рывок, дальше платный рост": {"extra_start_users": users_to_buy},
    "Рывок, дальше бесплатный рост": {"extra_start_users": users_to_buy,
                                      "free_growth_after": True},
}

strategy_runs = {}      # расчет за горизонт — пригодится для графика
rows = {}
for name, options in strategies.items():
    run = simulate(BASE, **options)
    strategy_runs[name] = run

    # Месяц окупаемости ищем на длинном расчете: накопленный итог впервые ≥ 0
    total = simulate(BASE, months=LONG_MONTHS, **options)["Дисконтированная прибыль"].cumsum()
    back = total.index[(total >= 0) & (total.index > 0)]

    rows[name] = {
        "Привлечение, млн руб.": fmt(run["Привлечение"].sum() / MLN, 1),
        "Доход, млн руб.": fmt(run["Доход"].sum() / MLN, 1),
        f"NPV за {BASE['months']} мес., млн руб.": fmt(npv(run) / MLN, 1),
        "Окупается": when(int(back[0]) if len(back) else None),
    }
strategy_table = pd.DataFrame(rows).T
display(strategy_table)

  • При росте 3% в месяц сеть дойдет до нее только на 112-м месяце (больше 9 лет) — втрое позже конца горизонта. За 36 месяцев сеть вырастает до 14,5 тыс. пользователей, это 10,9% критической массы.
  • Сеть теряет около 2 млн руб. каждый месяц. Доход с пользователя (15 руб.) целиком уходит на оплату роста (500 руб. × 3% = 15 руб.), и на поддержание не остается ничего. За 36 месяцев доход 4,89 млн руб., а затраты 76,75 млн руб. (72,00 поддержание и 4,75 привлечение).
  • NPV = −60,10 млн руб. При заданных параметрах проект убыточен.
  • Привлечение не окупается за горизонт. CAC возвращается за 33,3 месяца, а с учетом дисконтирования пользователь за 36 месяцев приносит 452 руб. при цене привлечения 500 руб.
  • Закон Мэткалфа. Пользователей стало больше в 2,9 раза, а ценность сети выросла в 8,4 раза (с 0,125 до 1,05 млн руб.): ценность растет как квадрат числа пользователей. При критической массе она была бы 88,9 млн руб., при охвате всего города — 5 млрд руб. То есть основная ценность возникает на поздних стадиях, до которых проект в базовом варианте не доходит. Закон Мэткалфа — оценка сверху: по более осторожному закону Одлыжко ($V \sim N \ln N$) ценность выросла бы только в 3,3 раза.

3.2. Сравнение с альтернативными вариантами¶

  • Темпы роста (задание 7). NPV почти не меняется: −59,09 млн руб. в пессимистичном сценарии, −60,10 в базовом, −63,74 в оптимистичном. Быстрый рост внутри горизонта даже ухудшает результат: расходов на привлечение больше, а критическая масса все равно не достигается (в лучшем случае — на 68-м месяце).
  • Минимальный ARPU (задание 8). Проект перестает быть убыточным при ARPU около 197 руб. в месяц — в 13 раз выше заданного. В этой точке NPV меняется скачком: при 196 руб. он равен −2,86 млн руб., при 197 руб. уже +0,49 млн руб. Причина — критическая масса $F / ARPU$ опускается до 10 164 пользователей, сеть набирает их к 24-му месяцу и с 25-го растет на 15%. Если темп роста не меняется, нужен ARPU 242,6 руб.
  • Ускорение на 6 месяцев (задание 9). Нужно разово привлечь на старте 970 пользователей, это 485 тыс. руб. Критическая масса тогда достигается на 106-м месяце вместо 112-го. Внутри 36 месяцев эти вложения не окупаются (NPV снижается на 0,46 млн руб.), выигрыш появляется позже: на отрезке 15 лет NPV улучшается на 19,7 млн руб.
  • Стратегии запуска (сверх условия). Привлечение до критической массы стоит 64,2 млн руб. при любой скорости, а медленный путь добавляет к этому 112 месяцев поддержания по 2 млн руб. Если купить недостающих пользователей сразу и дальше сеть растет бесплатно, рынок насыщается на 15-м месяце, и NPV за 36 месяцев равен +216,9 млн руб. Если и дальше платить по 500 руб. за пользователя, NPV за 36 месяцев равен −175,7 млн руб., а окупаемость наступает только на 58-м месяце. Медленный рост по условию не окупается и за 15 лет.

4. Выводы и рекомендации¶

4.1. Ключевые выводы¶

  1. Критическая масса сети — 133 334 пользователя. При заданном росте 3% она достигается на 112-м месяце, далеко за горизонтом оценки.
  2. NPV за 36 месяцев — −60,10 млн руб.; в пессимистичном и оптимистичном сценариях −59,09 и −63,74 млн руб.
  3. Причина убытков — сочетание низкого ARPU, дорогого привлечения и высоких постоянных затрат: при росте 3% весь доход уходит на покупку пользователей.
  4. Проект перестает быть убыточным при ARPU около 197 руб. в месяц; ускорение на 6 месяцев стоит 485 тыс. руб.
  5. За 36 месяцев проект окупается только в одном случае: быстрый набор критической массы и бесплатный рост после нее. Значит, судьбу проекта решает сетевой эффект, а не объем рекламы.

4.2. Практические рекомендации для «ГородСоцСеть» (задание 10)¶

  1. Не растягивать путь до критической массы. Каждый месяц ожидания стоит 2 млн руб. Бюджет на привлечение лучше потратить в начале, а не размазывать на годы.
  2. Набирать критическую массу локально. Запускаться не на весь город сразу, а по районам, вузам, жилым комплексам: в небольшом сообществе сеть становится полезной быстрее и дешевле.
  3. Снижать CAC за счет самого сетевого эффекта. Приглашения друзей, вход через существующие сервисы, партнерства с городскими организациями — рост должен становиться бесплатным как можно раньше.
  4. Повышать ARPU. 15 руб. в месяц не покрывают даже стоимость роста. Подходит рекламная модель из лекции: бесплатно для пользователей, платят местные рекламодатели; плюс платные объявления и сервисы для организаций.
  5. Снижать постоянные затраты на старте: чем они ниже, тем ниже критическая масса.
  6. Проверить бесплатный рост на пилоте до крупных вложений: если после локальной критической массы сеть не растет сама, расширять проект нельзя.
  7. Решить проблему «курицы и яйца»: дать пользу и без сети — городские новости, афишу, сервисы, — чтобы первым пользователям было зачем приходить.
